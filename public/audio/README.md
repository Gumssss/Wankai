### 用户语音的处理记录

三条原始录音都是 48 kHz 立体声 AAC（192 kbps），是手机双麦克风对着扬声器录下的：左右声道相差约 4–5 个采样（直接混成单声道会在 4–6 kHz 产生梳状滤波）；整体音量偏小（约 -26 / -26 / -23.5 LUFS）；本底噪声很低（约 -75 dBFS），没有削波和直流偏移。“录像感”主要来自三点：小扬声器几乎放不出 500 Hz 以下（低频比正常近讲人声少 20 dB 以上），1–5 kHz 偏亮且有共振峰；房间混响（字与字之间的拖尾，低频衰减更慢）；开心小猫还带着合成器伴奏。AAC 编码在约 16 kHz 以上没有内容。

当前版本（第二版，Python + numpy/scipy）：

1. 按分数采样延迟对齐右声道后与左声道平均成单声道（同第一版）。
2. 晚期混响抑制：按指数衰减模型（RT60 低频 0.9 秒、1 kHz 以上 0.4 秒）估计直达声 40 ms 之后的混响能量，用带下限（-8/-10 dB）且经平滑的维纳增益削减，只处理拖尾、保留早期反射，无“音乐噪声”。肥嘟嘟字间停顿的拖尾能量下降 6–9 dB（相对语音）。试过双麦克风 WPE 去混响，两只麦克风距离太近、片段太短，只有 0.1–0.6 dB 效果，未采用。
3. 轻度稳态降噪（以开头空白为噪声样本，最多 -9 dB）；零相位高通：大笑、肥嘟嘟 80 Hz，开心小猫 480 Hz（4 阶；人声基频约 580 Hz 以上，再陡会让 “happy” 听起来像 “help me”）。
4. 开心小猫去伴奏：试过 Demucs（HDemucs 人声分轨），它把这段变调的猫声整段判成“其他乐器”，分不出人声，未采用。改为两步：把频率恒定的谱线（合成器音符；人声谐波有滑音和颤音，不受影响）用平滑的窄陷波压低 20 dB；再用结尾纯伴奏段（3.65–6.2 秒）的平均频谱做带下限的维纳抑制。纯伴奏段整体下降 9 dB，人声段只下降约 2–3 dB（其中约 1.8 dB 来自去混响）。
5. 裁剪：大笑 1.78–5.13 秒（300 ms 淡出）；肥嘟嘟 2.66–4.71 秒（50 ms 淡出；比第一版早结束约 0.1 秒，去掉句尾之后的一声低频碰触声）；开心小猫 1.33–3.04 秒（70 ms 淡出）。
6. 频谱校正（替代第一版的固定均衡）：对比近讲语音长期平均频谱（Byrne 1994），按 1/3 倍频程算出差值的一部分，并按频段限幅：500 Hz 以下最多 +4 dB（补回扬声器放不出的“厚度”），500 Hz–6 kHz 最多 +2 dB，6–12.5 kHz 最多 +3 dB（空气感），宽带削减最多 3 dB；另把 0.8–6 kHz 中明显高出周围的共振峰削掉一部分（最多 -4 dB）。开心小猫是高音变调声，只在 600 Hz 以上做较轻的校正。用线性相位 FIR 实现。
7. 齿音抑制（5–10 kHz 分频动态衰减，最多 5 dB）；很轻的高频激励（由 6–8 kHz 生成 12 kHz 以上的谐波，比原频段低约 28–30 dB），补一点 AAC 截掉的“空气”。
8. 轻压缩（2:1，最大约 5 dB）；大笑另加轻微瞬态增强；肥嘟嘟加轻度向下扩展（1:1.6，最多 5 dB），避免压缩把字间拖尾又抬起来。
9. 响度统一到 -16 LUFS，真峰值 ≤ -1.2 dBTP，TPDF 抖动后存为 48 kHz 16-bit 单声道 WAV。

客观验证（与第一版比较）：肥嘟嘟字间停顿能量（相对语音）由 -18 / -19 / -31 dB 降到 -23 / -22 / -38 dB；大笑包络起伏深度 8.5 → 8.8 dB（原始 6.9 dB）；低频比例明显提高（肥嘟嘟 80–1000 Hz 能量 +4–6 dB，大笑 +4–5 dB），1–4 kHz 略降；无削波、无直流。faster-whisper 识别：肥嘟嘟三版都识别出全部 10 个字（“胆子”一直被听成同音的“單字”，“嘟嘟”在“嘟嘟/肚肚”间摇摆，原始录音也一样）；开心小猫三个 “happy” 的识别率 0.67（第一版）→ 0.78（第二版），原始约 0.75。

已知限制：开心小猫的伴奏只是减弱，没有完全去掉——合成器有时和人声同音高，或在人声停顿处持续发声，这些部分无法和人声区分；伴奏的打击/铺底音也只削了一部分。大笑这段本身是连续笑声，没有明显停顿，去混响效果主要体现在“哈”与“哈”之间更清楚。处理脚本没有入库。

### 背景音乐的选曲与处理记录

**授权**：四首都来自 incompetech.com，Kevin MacLeod 作曲，Creative Commons Attribution 4.0（可商用，必须署名）。署名在游戏「设置 → 音乐署名」里显示（数据在 `src/audio/credits.js`），格式按作者要求：曲名、`Kevin MacLeod (incompetech.com)`、`Licensed under Creative Commons: By Attribution 4.0` 加许可链接，并注明做过剪辑。新增或替换音乐时必须同步更新 `credits.js`；`tests/audio.test.js` 会检查 `music/` 里的每个文件都有署名。没有选用 Pixabay（有视频被 Content ID 认领的报告）、YouTube 音频库（授权只针对 YouTube 视频）和来源不明的“免版权 BGM”合集。

**选曲**：原合成曲是玩具箱配器（马林巴、拇指琴、毡锤钢琴），菜单 96 BPM、对战 132 BPM。候选曲用 incompetech 的曲目数据（BPM、配器、风格标签）初筛，再按信号分析结果定曲：速度是否恒定（逐 30 秒检测）、整首能量是否平稳（3 秒短时响度）、能否切出接缝干净的长循环。
- 菜单 Daily Beetle：尤克里里、马林巴、八音盒、玩具钢琴，和原合成曲配器最接近；固定 100 BPM。备选 Carefree、Life of Riley 母带偏轻、配器没那么“玩具”。
- 玩具庭院 Mischief Maker：木琴、扬琴、维金纳琴加鼓组，调皮又有推进感；固定 125 BPM，64 小节段落几乎原样重复（接缝处波形相关 0.999）。淘汰 Quirky Dog（摇摆节奏，节拍网格对不齐，无法无缝循环）、Run Amok（管弦乐动态起伏大，只有 1:47）。
- 罗马角斗场 Bushwick Tarantella：意大利塔兰泰拉，手风琴和单簧管。完整版的速度在 208–218 BPM 之间漂移，找不到干净的长循环；Loop 版速度恒定（214.8 BPM），但整段首尾相接有 +14 dB 的跳变，所以取它中间 144 拍的一段。淘汰 Movement Proposition（中段有一次大停顿）。
- 湖中庭院 Shenyang：二胡、琵琶、扬琴加打击乐，明亮的中国民乐风，配汉白玉栏杆、荷花和六角亭；固定 130 BPM。曾试 Guzheng City（节拍弱、中间有停顿，切不出好循环）和 88.6 秒的 Shenyang 长循环（接缝落在音符中间，波形相关只有 0.48），最终用 32 小节的循环。

**处理流程**（Python + numpy/scipy/soundfile；脚本没有入库）：
1. 解码 MP3，用频谱通量的起音包络在 ±3% 范围内细调 BPM 和第一拍相位，得到恒定节拍网格。
2. 每拍提取 12 维色度（和声）和 24 段对数频带能量（配器/音色），在所有“起点拍 × 长度（整小节）”组合中找接缝两侧 ±4 秒最相似的循环；排除原曲结尾的收束段。
3. 起点和终点提前 12 ms（保住重拍的起音），终点在 ±12 ms 内按波形互相关微调；循环开头 50 ms 与终点之后的原曲做交叉淡化（相关性高时线性，低时等功率），所以循环回到开头时和原曲连续演奏一样。
4. 所有滤波都按循环处理（前后拼接自身再滤波、取中段），接缝不会因滤波产生突变：30 Hz 高通；两首对战曲（Mischief Maker、Tarantella）在 3 kHz 削 1.5 dB（Q 0.9），给武器打击声留空间。
5. 响度按原合成曲对齐（用 OfflineAudioContext 渲染原 `MusicPlayer` 测得：菜单 -17.2 LUFS，对战 -15.0 LUFS）：菜单 -17 LUFS，对战曲 -15 LUFS（ITU-R BS.1770）；4 倍过采样的真峰值超过 -1 dBTP 时用前瞻限幅器压到 -1.2 dBTP。
6. 导出 44.1/48 kHz 立体声 OGG Vorbis（约 200–220 kbps）。不用 MP3：MP3 编码器会在首尾补静音，循环时会有空隙。在 Electron 里用 `decodeAudioData` 验证过：时长和循环长度完全一致；循环播放时接缝处的采样跳变（约 0.02）远小于曲内 99.9 分位的跳变（0.07–0.22），没有爆音。接缝前后 250 ms 的电平变化与原曲在循环起点、终点处本来就有的变化相当（相差 0.03–1.1 dB）。

## 可替换的声音槽位（可选）

把真实音频文件放进下面的位置即可替换合成占位音，**不需要改代码**。游戏在第一次解锁声音时（第一次点击/按键）依次尝试 `.mp3`、`.m4a`、`.ogg`、`.wav`，找到第一个能解码的文件就使用；找不到或解码失败时自动退回合成音。

| 文件名（任选一种扩展名） | 触发时机 | 没有文件时的合成占位 |
| --- | --- | --- |
| `voices/naiwa-laugh.mp3` | 奶蛙技能「大笑」（skill `laugh`） | 憨憨的“哈-哈-哈-哈-哈-哈”大笑 + 吸气声，约 2.6 秒 |

| `voices/happy-cat.mp3` | 开心小猫回血（skill `happy`） | 尖细猫声 “hap-py hap-py hap-py”，约 1.8 秒 |

- 目前三条角色语音已经放入用户提供的 `.wav`（见上方素材表）。注意加载顺序是 `.mp3` 优先，若再放入同名 `.mp3` 会覆盖 `.wav`。
- 语音播放时背景音乐会自动压低；同一条语音不会叠播（再次触发会淡出旧的、重新开始）。
- 建议：单声道或立体声、44.1/48 kHz、峰值约 -1 dBFS、首尾不留长静音，时长 1–4 秒。

## 规则

- 文件名使用英文小写和连字符；新增素材时在上方素材表记录来源与用途，并确认拥有使用授权。
- 开发服务器（Vite）对不存在的文件会返回 index.html，代码会把“无法解码”当作“文件不存在”处理，所以槽位留空是正常的。
- 音乐使用第三方授权素材时，在 `src/audio/credits.js` 中加入署名（游戏内「设置 → 音乐署名」显示）。
